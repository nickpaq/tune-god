# KoalaTune notes for Claude sessions

- Koala mixer facts (buses, plugin names, parameter ranges, what is still unconfirmed): `docs/koala-mixer-reference.md`. Read it before touching `src/audio/mixerChain.ts` or `src/audio/routing.ts`.
- Bus layout the export writes: A Kick, B Bass, C Drums, D Melodic (with vox and FX), Main for Other. The kick has a bus alone so the bass bus can be sidechained from it.
- The OLED screen text is sized in whole device pixels (`--c`, set by `src/components/useOledCell.ts`). Size anything on the screen in multiples of `--cell`; Silkscreen's pixel is 1/8 of its font size. The cell comes from the phone's width alone and is never stepped down or grown to fit: the text is one consistent size everywhere (an earlier fit-to-screen loop made it jump between sizes and was removed). Keep new screen content within the screen at that size; use `text-overflow: ellipsis` where a line may be long.
- **Bank D (pads 48 to 63) is the chops' bank and nothing else.** No tool (the four bank loaders, the extra-drums export option, `nextEmptyPad`) puts anything there, not even an Empty pad placeholder, and none moves anything in or out of it: tools work on banks A to C only (`TOOL_PAD_COUNT`, `inChopBank` in `src/audio/padMoves.ts`). Sounds that find no pad in banks A to C go to the hot-swap pool. Only the chop's section pads go to bank D, and the chop puts them nowhere else (`freeSongSlots` is bank D only; a new chop replaces the last one). Tested in `chopBank.test.ts` and `fingerDrumming.test.ts`.
- The UI is the Graphite · Barlow design only (spec: `docs/graphite-barlow-redesign-spec.md`). There are no drawers or older themes left.
- **The four banks are loaded by four menu buttons, each locked to its bank** (`src/audio/bankLoad.ts`, `loadBank` in `App.tsx`, writer `writeBankSounds` in `packProject.ts`): **Load Bank A: Drums** (a pack with subfolders; type by subfolder name, never file name; 10 kicks, 10 snares, 5 closed + 5 open hats, 5 of every other drum type; fills the drum layout), **Load Bank B: Melodic Loops** (a folder with no subfolders; 12 at random on pads 16 to 27, plus spares), **Load Bank B: 808 & Bass** (808/bass subfolders; two basses then two 808s on pads 28 to 31), **Load Bank C: One Shots** (a folder with no subfolders; 16 at random on pads 32 to 47) and **Load Bank D: Acapella (Koala project)** (bank D, `src/audio/acapella.ts`: only the song and its vocal stem are read out of the zip and handed to the chop editor, the zip is never opened as the project). Loops and one-shots over 30 s are skipped. Sounds are written under numbered names ("Kick 1.wav", "808 1.wav", "Loop 3.wav", "One Shot 2.wav") and labelled from them (`numberedLabel`); bass, melodic loops and one-shots (category `melodic`) are tuned by default. Loading a bank again (no question asked) replaces that bank's pads and spares only. A loader with no project open starts a blank one (`blankProject`: one silent pad that loading ignores and the export drops). The project size limit defaults to 512 MB (`packByteBudget`). A dropped folder is a Bank A load. Folder inputs live in the menu's parent and must stay mounted outside the menu (closing the menu unmounts them). A kit slot held by a stand-in is no longer replaced separately: Bank A loading replaces the whole kit. **The loaders own placement, labels, colours and tuning defaults**: nothing afterwards moves, relabels or recolours a pad (no Organize sorting, no drum-layout switching, no palette picker, no type-driven moves; changing a sound's type in the Type mode keeps the pad where it is). The only layout is the MPC default (`horizontal` in `fingerLayouts.ts`), written by Load Bank A. The empty start screen offers four pixel-icon buttons (`dropIcons.ts`: K = open a .koala project, drum = Load Bank A: Drums, keys = Load Bank B: Melodic Loops, K with a person and a note = Load Bank D: Acapella) that call the same loaders as the menu; it has no deck, so its text has the room, and a screen with fewer than 90 text rows (`data-tight`, set by `useOledCell`) drops the words under the icons. A pad that holds a sound shows only its name ("Loop 6"); the slot number shows only on pads with nothing to say.
- Remote branch deletion returns 403 in the cloud sandbox, so delete merged branches by hand.
- Koala has two EQs: a per-pad EQ in `sampler.json` (`pad.eq`, lo highpass / mid peaking / hi highshelf) and an EQ plugin in `mixer.json`. The measured min and max values in the reference are for the mixer plugin.
- All sound-shaping numbers (loudness trims, per-pad EQ, bus effects, master chain) live in one preset object, `src/audio/mixPresets.ts`. Add a genre by copying it; the guide is `docs/mix-presets.md`. Do not scatter new mix numbers elsewhere.
- **The app runs on a 402 x 874 CSS viewport (an iPhone 16 Pro, installed). Design, build and test for that size only: screenshots, browser tests and layout checks use a 402 x 874 viewport, and no other size or phone is considered.** Layout height is the viewport as reported (`height: 100%`); do not force the screen height on installed iOS apps (it clipped the transport row on iOS 26). Safe areas still come from `env(safe-area-inset-*)` and `useSafeArea.ts`, never from hard-coded numbers. The OLED is a size container: its text is sized in cells and every view must fit its screen at 402 x 874.
- The menu ends with the version line (`package.json` version and the git hash, injected by `vite.config.ts` as `__APP_VERSION__` and `__APP_BUILD__`) and the active mix preset. Bump `version` in `package.json` when something users could notice changes, and check the line when testing a build: the PWA caches the old version until it updates.
- `public/viewport-test/` is a diagnostic page (numbered grid, gradient and a readout of every viewport size) served at `/viewport-test/` on the production domain, which needs no Vercel login, as its own installable web app. The `viewport-test` branch holds the same page alone, but branch previews sit behind Vercel's login. Remove the folder (and the `navigateFallbackDenylist` line in `vite.config.ts`) once the render area is settled.
- Koala mixer behaviour is measured with the projects in `docs/calibration/` (the mix calibration project, `probe-sidechain.koala`, `probe-eq.koala`) and the scripts `analyzeMixRender.py` and `analyzeMixerProbes.py`. Measure with the master chain off first: the master limiter and compressor distort any comparison between renders (round 1's sidechain depth was such an artifact). Velocity is linear (gain = vel / 127).
- New calibration and probe projects put every test in one long pattern (sections back to back, with an empty bar between them), not several patterns, so the user renders one pattern. Write the timeline for that single pattern. All projects in `docs/calibration/` now follow this.
- The menu has two sound-shaping switches (`Switch` in `App.tsx`, the lit key from under the piano). **Organize** is the old Mix and Master chain in one: balance loudness, route to buses, settings by sound type, melodic spread and the master chain (`normalize`, `routeBuses`, `autoPlayback`, `spread` and `masterChain` all read it); "Normalize now" and the master style list (Dynamic or Loud, `MasterStyle` in `mixPresets.ts`) sit under it. It never moves, labels or colours a pad. **Sidechain** is its own switch: it needs Organize on and a kick and a bass or 808 on the pads (`sidechainStatus` in `src/audio/sidechain.ts`, worked out from the pads each render, so a hot swap or a new kit locks or unlocks it at once); it is written only when both are present. The export assigns buses from each pad's current type, so routing always follows what is on the pads (tested in `sidechain.test.ts`). The export can no longer write placeholder pads (the writer is gone): every exported pad has a real sample; the on-screen "add FX" and Empty placeholders are never exported. Pads from the loaders are written with the colour and label they show; a sound from an opened project keeps its own.
- `buildTunedKoala` writes into the project's zip (audio, `mixer.json`, `sequence.json`), so `exportProject` in `App.tsx` re-parses `projectFile.current` for every export. Reusing one parsed project for a second export carried the first export's master chain, bus plugins and remapped patterns into it (switching the master style then did nothing and the pattern remap ran twice). Keep that fresh parse.
- A long song can be chopped into section pads with a pattern each, cut along a grid the user taps out (long-samples prompt, "Chop to patterns for acapella"). The project must hold the song and its Koala stem-split vocal stem (its pad **label** is the song pad's label plus " VOCALS", not the file name; checked by `checkStems` before anything opens): the cuts are found on the song and made on the stem. Section pads are virtual like ghost pads (`Pad.section`, not `isReal`) and are written by `addSongSections` in the export. The cut arithmetic must stay exact to the frame (`planSections` (`tapGrid.ts`), tested), and the editor layout must stay fixed while dragging. Guide: `docs/song-chop.md`.
- The chopped vocal pads are written with stretch on and `stretchLength` = the pattern's bars x the project's beats per bar: Koala counts the stretch length in **beats** (read from `docs/calibration/stretch-5-bars.koala`: 5 bars of 4/4 is 20). That project also records the attack, release and tone knob fields; see "Stretch, attack, release and tone" in `docs/koala-mixer-reference.md`.
- The Tune screen's **pitch slider** is the selected pad's pitch trim (`moveTrim`, `startMatch`, `stopMatch` in `App.tsx`; `PadPanel.tsx`, `PrecisionSlider.tsx`). Grabbing it starts the pad looping at its current tuning with the reference tone on the key; **both play only while it is held** and stop on release, and the pad keeps the pitch it was left at (there is no Correct button and nothing snaps back). Dragging **along** the slider goes by whole semitones, **down** goes finer (as before) and **up** depends on the sound: a **melodic loop** shows two squares on the screen, Minor at the top left and Major at the top right with the playing chord lit, and moving the finger onto the other one swaps the reference chord for the relative key's (see below); any other sound has nothing up there (the old YIN failure-mode stops are gone). Double-tap resets the trim. The Tune deck (piano, ALL, TONE) is 12cqw tall, `.deck--tune`; the pad height still reserves `--screen-min` + `--deck-min` (34 + 22).
- **Melodic loops are keyed from chroma, not YIN** (`src/audio/pitch/loopKey.ts`, using `chromaOf` and `keyOfChroma` from `song/beats.ts`): the result is the key's relative minor tonic as a whole MIDI note (C major and A minor are one answer), never cents. `shiftFor` moves a loop by whole semitones to the project key (the A4 reference is ignored for loops); anything else it is off by, the user tweaks. The Tune deck's **Minor/Major key** (`keyMajor`, the key beside the piano that used to be All/One; "tune one pad" is gone, a key always retargets every pad) says whether the key picked on the piano is a minor key (default) or a major one (the loop then goes to the relative minor a minor third below). The reference tone for a melodic loop is a soft saw minor or major chord on that key (six detuned saws through a low-pass, `createTone` in `player.ts`); every other sound and the piano keys use a plain sine. The Minor and Major squares (`chord-box` in `PadPanel.tsx`, shown while the finger is above the slider) swap the reference chord for the relative key's (a minor key's relative major, a major key's relative minor), live; the choice is remembered on the pad (`Pad.refRelative`), so a loop is its project key's own chord until the user switches it and then that pad's reference stays the relative key's; they never change the project key.
- **SEQ (the sequencer)**: a SEQ key beside TUNE, TYPE and SWAP opens `src/components/seq/SeqScreen.tsx` (styles in `seq.css`, sized in `--px`, one 402nd of the phone's width). It is the interface only: nothing on it plays, records or writes a pattern yet, and keys, sliders and switches keep their own state. Pages: Play (the app's own pads for the bank), Velocity, Pattern, Sample edit, Tempo, Mixer, Keys (bank D, drawn to the Koala reference's exact geometry) and Sounds (the hot-swap list for the selected pad, shared with the Swap mode through `swapListFor`). The drawings, plan and latency findings are in `docs/seq-designs/` and `docs/seq-sequencer-plan.md`. Back replaces Stop in the transport row.
