# KoalaTune notes for Claude sessions

- Koala mixer facts (buses, plugin names, parameter ranges, what is still unconfirmed): `docs/koala-mixer-reference.md`. Read it before touching `src/audio/mixerChain.ts` or `src/audio/routing.ts`.
- Bus layout the export writes: A Kick, B Bass, C Drums, D Melodic (with vox and FX), Main for Other. The kick has a bus alone so the bass bus can be sidechained from it.
- The OLED screen text is sized in whole device pixels (`--c`, set by `src/components/useOledCell.ts`). Size anything on the screen in multiples of `--cell`; Silkscreen's pixel is 1/8 of its font size.
- The UI is the Graphite · Barlow design only (spec: `docs/graphite-barlow-redesign-spec.md`). There are no drawers or older themes left.
- Add pack lives in the menu; its folder input must stay mounted outside the menu (closing the menu unmounts it).
- Remote branch deletion returns 403 in the cloud sandbox, so delete merged branches by hand.
- Koala has two EQs: a per-pad EQ in `sampler.json` (`pad.eq`, lo highpass / mid peaking / hi highshelf) and an EQ plugin in `mixer.json`. The measured min and max values in the reference are for the mixer plugin.
- All sound-shaping numbers (loudness trims, per-pad EQ, bus effects, master chain) live in one preset object, `src/audio/mixPresets.ts`. Add a genre by copying it; the guide is `docs/mix-presets.md`. Do not scatter new mix numbers elsewhere.
- Layout height is the viewport as reported (`height: 100%`); do not force the screen height on installed iOS apps (it clipped the transport row on iOS 26). Measured with the viewport test page on an iPhone (installed, iOS 26, 402 x 874 pt screen): the page is **402 x 812**, drawn from the top of the screen under the status bar, with 62 pt of black under it; `100vh`/`100lvh` say 874, `100dvh`/`100svh` 812; the top safe area is 62 and the reported bottom one 34, but the home indicator is in the black strip, so `useSafeArea.ts` takes the lost 62 pt off the bottom inset (`--safe-bottom`, 0 there). The pad height (`--pad-h`) is worked out from the height left after the safe areas, so pads get shorter (wider than tall) on a phone with a big top inset instead of pushing over the piano. The OLED is a size container: wider than 2:1 in cells means a short screen and the drop zone switches to its compact layout (`@container` in `App.css`).
- The menu ends with the version line (`package.json` version and the git hash, injected by `vite.config.ts` as `__APP_VERSION__` and `__APP_BUILD__`) and the active mix preset. Bump `version` in `package.json` when something users could notice changes, and check the line when testing a build: the PWA caches the old version until it updates.
- `public/viewport-test/` is a diagnostic page (numbered grid, gradient and a readout of every viewport size) served at `/viewport-test/` on the production domain, which needs no Vercel login, as its own installable web app. The `viewport-test` branch holds the same page alone, but branch previews sit behind Vercel's login. Remove the folder (and the `navigateFallbackDenylist` line in `vite.config.ts`) once the render area is settled.
- Koala mixer behaviour is measured with the projects in `docs/calibration/` (the mix calibration project, `probe-sidechain.koala`, `probe-eq.koala`) and the scripts `analyzeMixRender.py` and `analyzeMixerProbes.py`. Measure with the master chain off first: the master limiter and compressor distort any comparison between renders (round 1's sidechain depth was such an artifact). Velocity is linear (gain = vel / 127).
- New calibration and probe projects put every test in one long pattern (sections back to back, with an empty bar between them), not several patterns, so the user renders one pattern. Write the timeline for that single pattern. All projects in `docs/calibration/` now follow this.
- The menu has switches (`Switch` in `App.tsx`, the lit key from under the piano): **Mix** (balance loudness, route to buses with the bass sidechain, settings by sound type, melodic spread; `normalize`, `routeBuses`, `autoPlayback` and `spread` all read it), **Master chain** with a style list (Dynamic or Loud, `MasterStyle` in `mixPresets.ts`, each with its own chain), **Organize** (colours and labels, and the sorting step) and **Drum layouts** (locked until Organize has sorted every sound; `organized`). Organize first settles sounds by file name (`planOrganize` in `src/audio/organize.ts`), then walks the rest one by one in a focus mode (`focus` state: a dark overlay, the type keys and the current pad raised above it, a cross at the top left that warns before leaving). A sample pack counts as organized from its folders.
- `buildTunedKoala` writes into the project's zip (audio, `mixer.json`, `sequence.json`), so `exportProject` in `App.tsx` re-parses `projectFile.current` for every export. Reusing one parsed project for a second export carried the first export's master chain, bus plugins and remapped patterns into it (switching the master style then did nothing and the pattern remap ran twice). Keep that fresh parse.
- A long song can be chopped into 8-bar section pads with a pattern each (long-samples prompt, "Chop to patterns for acapella"). Section pads are virtual like ghost pads (`Pad.section`, not `isReal`) and are written by `addSongSections` in the export. The cut arithmetic must stay exact to the frame (`planSections`, tested). Guide: `docs/song-chop.md`.
