# KoalaTune notes for Claude sessions

## Consolidated product specification (v1.14.0)

These rules supersede older conflicting notes below. Implementation and validation details: `docs/consolidated-product-spec.md`.

- Load hot-swap spares defaults OFF. New kits load only their 48 pad sounds, excluding locked slots from loading quotas. Connected-library hot swap browses metadata with search and an infinite scroll (50 rows at a time, more as the list is scrolled; there are no pages), decoding only the single sound requested by Shuffle, preview or selection. Favorites also decode on demand. A corrected sound can remain as a spare even when preloading is off; refill its original Type directly from the connected library whenever connected.
- The menu highlights Build another kit, which opens pack selection and clears every bank only when the kit is generated (closing the picker with X leaves the loaded sounds alone: `buildFreshKit` in `App.tsx`). Keep kit/memory, library tools, individual bank loaders, project/sound settings and appearance under collapsible groups. Replace kit · keep bank D stays under Library tools for replacing only A–C.
- Cents mode wraps the hand to the opposite side when crossing a semitone midpoint; retain the total cents value instead of resetting it to the new semitone anchor.
- Tune has no floating pitch label or BPM/Stretch row. The top Shift readout reports tuning and the waveform has a playback line. Preserve the slider, keyboard and pad geometry; use the released BPM-row space for the waveform. Stretch remains configurable in Koala Type & pad settings.
- A manual Type correction remembers the corrected sound's metadata and moves it into hot swap, then refills the same slot from a spare of the original intended Type. For a hat corrected to Vox, retain the vocal as a spare and load another hat. No matching spare means a labeled gap; locked pads are corrected in place until unlocked. Never relabel an unrelated replacement as the requested Type.
- Library selection reconnects files each session and restores metadata from IndexedDB, with no whole-library audio stored. Classify from the complete hierarchy, filenames, aliases and saved corrections, keeping confidence and review status. Bass loops, vocal loops and FX loops are separate Types. Subtypes are removed: risers, falls and sweeps are FX; crashes are Cymbal; rims are Snare. Performance takes priority over detailed classification.
- Bank A defaults to Cymbal / FX / FX / FX / Perc / Perc 2 / Perc / FX / Kick 2 / Snare 2 / Snare 3 / Clap / Kick 1 / Snare 1 / Closed Hat / Open Hat 2. This is the single fixed MPC preset; template editing and additional-bank selection are removed. Generation honors sample locks.
- Generate kit always fills A–C. B and C both contain organized rows of mixed bass, melodic one-shots, vocals, FX and loops. D is reserved for chops and acapellas and is never automatically filled. Existing direct bank loaders remain available.
- Match requested Types first, then randomly fill missing pads with available Types, preserving their actual classification. Tiny libraries may share sample audio across independent pads. Never display a missing-pad shortage notice. Balance packs when selected. Decode quotas are shared by Type, with four spares per requested Type; analysis copies are allocated only when a worker job starts. Supporting vocals/FX on B/C are intentional sounds, not unused drums.
- Koala buses 1–4 (serialized 0–3): Kick/Bass, Drums, Melodic, Loops/Vox/FX. Bass one-shots AND bass loops default to choke 5. Hats 1, cymbals 2, drum loops 3, melodic loops 4, vocal loops 6. All loop Types default to One Shot off / Stretch on; one-shots default to One Shot on / Stretch off. Type defaults < user Type settings < saved per-pad overrides. Settings are keyed by original pad, not sampleId, so pads sharing audio can differ. Keep metadata and classify through export; only explicit pad overrides are persisted as overrides.
- Acapella alone has Chop by 4 and Chop by 8. Synced mode retains waveform scrubbing, zoom, grid nudges and its explicit anchor. Tempo detection uses a repeated clear low-frequency accent to improve provisional bar-1 placement, falling back to its tracked beat for ambiguous material; a user anchor always wins. The destination selector provides separate speaker preview without changing selection.


- **Terminology (the user's):** "chopper mode" means only the sub-mode called Chopper in the Chop a long sample menu. "Acapella mode" and "synced mode" mean the sub-modes of those names. Do not use "chopper" for the whole menu or for the other two modes. **Acapella mode's file picker must take a .koala project or two audio files (the song or instrumental and its acapella, same length)**: its input has no `accept` filter, because on iOS a filter listing audio beside .koala greys the project out (it broke twice); `loadAcapella` sorts the picked files by extension.
- Koala mixer facts (buses, plugin names, parameter ranges, what is still unconfirmed): `docs/koala-mixer-reference.md`. Read it before touching `src/audio/mixerChain.ts` or `src/audio/routing.ts`.
- Bus layout the export writes: A Kick, B Bass, C Drums, D Melodic (with vox and FX), Main for Other. The kick has a bus alone.
- The OLED screen text is sized in whole device pixels (`--c`, set by `src/components/useOledCell.ts`). Size anything on the screen in multiples of `--cell`; Silkscreen's pixel is 1/8 of its font size. The cell comes from the phone's width alone and is never stepped down or grown to fit: the text is one consistent size everywhere (an earlier fit-to-screen loop made it jump between sizes and was removed). Keep new screen content within the screen at that size; use `text-overflow: ellipsis` where a line may be long.
- **Chops in acapella and synced mode go to the pads the user picks, on any of the 64** (`PadAllocator.tsx`, `src/audio/chopDestinations.ts`; opened by the editor's two export buttons, **Chop to Multiple Patterns** and **Chop to One Pattern**): a four-bank selector where tapping an occupied pad plays its sample and selects it (red overwrite mark), the next tap deselects without playing; locked pads are never offered; chops are assigned Bank A to D ascending; the chop count is the destinations, the chops marked and (multiple patterns only) Koala's free pattern slots. The 16-chop limit is gone. The source is copied and checked before an overwrite (`sourceProtect.ts`), the result is written into a copy of the project and checked (`chopValidation.ts`) before the pads change, and the overwrite is confirmed. Cuts snap to a single beat (`beatChopLines`); `Chop by 8/16` is acapella mode's alone and only places markers. A chop section's pitch is `shiftFor` (live key move + trim) and is fitted to Koala's -12..+12 knob by `koalaPitch` (`pitchWrap.ts`, same pitch class in a reachable octave beyond that). Chops get one mute group no other pad uses, or One Shot off when none is free; note lengths never depend on it (`singlePattern`). Chopper mode writes a Koala chopper pad on bank D, 127 chops each; past 127 the pad is duplicated onto the next pad and the overflow is mapped to that copy (up to 2032). Haptics: `src/audio/haptics.ts`. Where this contradicts the Bank D rule below, this wins for the chop only; the tools still stay out of bank D.
- **Bank D (pads 48 to 63) is the chops' bank and nothing else.** No tool (the four bank loaders, the extra-drums export option, `nextEmptyPad`) puts anything there, not even an Empty pad placeholder, and none moves anything in or out of it: tools work on banks A to C only (`TOOL_PAD_COUNT`, `inChopBank` in `src/audio/padMoves.ts`). Sounds that find no pad in banks A to C go to the hot-swap pool. Only the chop's section pads go to bank D, and the chop puts them nowhere else (`freeSongSlots` is bank D only; a new chop replaces the last one). Tested in `chopBank.test.ts` and `fingerDrumming.test.ts`.
- The UI is the Graphite · Barlow design only (spec: `docs/graphite-barlow-redesign-spec.md`). There are no drawers or older themes left.
- **The four banks are loaded by four menu buttons, each locked to its bank** (`src/audio/bankLoad.ts`, `loadBank` in `App.tsx`, writer `writeBankSounds` in `packProject.ts`): **Load Bank A: Drums** (a pack with subfolders; type by subfolder name, never file name; 10 kicks, 10 snares, 5 closed + 5 open hats, 5 of every other drum type; fills the drum layout), **Load Bank B: Melodic Loops** (a folder with no subfolders; 12 at random on pads 16 to 27, plus spares), **Load Bank B: 808 & Bass** (808/bass subfolders; two basses then two 808s on pads 28 to 31), **Load Bank C: One Shots** (a folder with no subfolders; 16 at random on pads 32 to 47) and **Load Bank D: Chopper** (bank D, `askChopMode` in `App.tsx`: asks for Acapella mode or Chopper mode, `AcapellaModeModal`; with no project open it first picks a file: **acapella mode takes a .koala project or two audio files** (the song and its vocal stem, picked together; the stem is the file named vocals / acapella / vox / stem; `AcapellaFilesModal` then shows both files in the chopper selector's list style (play button, name, length) with a Song / Vocal button on each; pressing it swaps the roles (one song, one vocal always), and the first guess comes from the names via `guessAcapellaRoles`; `acapellaProjectFromAudio` in `packProject.ts` makes a project of them with the song on pad 48 and the stem, labelled "{song} VOCALS", on pad 49), **chopper mode takes an audio file only**; a .koala project opens as the project ignoring the 60 s limit. **Acapella mode** (`startAcapella`, `findAcapellaPair` in `src/audio/song/stems.ts`): the song and its VOCALS stem are looked for in pads 48 and 49, then anywhere in the project; no pair means an alert that both files are needed; it overwrites everything on bank D (warned, nothing is moved), 16 chops, changes the project BPM only when no key is picked on the piano (then it takes the acapella's, with the pitch knobs at 0), nothing is tuned, and a key picked on the piano is written to Koala's pitch knob on the section pads (`keyOffset`). **Synced mode** (`launchSynced` in `App.tsx`; the mode picker's third button; an audio file or a sample over 10 s, like chopper mode): acapella mode without the acapella, the markers are placed on the sample and the same sample is cut into 16 section pads (labelled "Chop N"). **Section pads in acapella and synced mode** are one-shot, stretch Modern, `stretchLength` the pattern's bars in beats, take the song pad's mute group (or 7 when it has none and no pad uses 7, else the next free group from 7: `sectionMuteGroup`), carry a highpass EQ (`sectionEq`), and their files are peak-normalized with the gain taken off on the volume knob. **Chopper mode** (`ChopperSourceModal`, `src/audio/exportChopper.ts`): any sample over 10 s (with no project open the picker takes an audio file only: `loadChopperAudio` starts a blank project and the chop editor opens on the file; the export writes the new project from it), one Koala chopper pad with up to 127 slices picked by velocity, one-shot, mono, play-through off, not stretched, and it sets the project BPM to the sample's (times the key offset's speed change). The chopper saves its markers per song and asks before X closes it). **Chopper mode's pattern maker (v1.0.0)** uses the shared `SectionWorkspace` (`PatternMaker.tsx` is a wrapper). The alignment editor also opens it directly before any chops are prepared. The current workflow is documented in `docs/section-workspace.md`: 1/2/4/8/16-bar source sections; interleaved regular/triplet lengths; short-left confirm, long-left silence, short-right selected-length trim, long-right rewind to last bar start, and undo; centered timeline and scrolling sequence playback; snapped one-off Wildcard selection preserving normal source alignment; triplet grid progress colors; top-left options menu, previous/next chop replacement, and a repeatable 16-step chop-length rhythm randomized from aligned source sections (vertical swipes replace sources with durations locked); future-only loop changes, continuous confirmed history/suffix, tap playback with optional extreme Stretch audition, Undo/Redo, and insertion of Repeat. The grid is snapshotted on opening; note timing stays in steps while quiet sample boundaries and short fades prevent clicks. Finished arrangements are packed into independent slices of a fresh WAV (127 unique pieces per pad, consecutive D1–D16 pads and separate WAVs, 2032 total max), so overlapping source ranges cannot interrupt each other; silence stays a gap, and ONE SHOT is off. Select the chopper pad and use Edit chop pattern to reopen during the session. Without Done the ordinary chop still keeps one pattern per chop. Loops and one-shots over 30 s are skipped. Sounds are written under numbered names ("Kick 1.wav", "808 1.wav", "Loop 3.wav", "One Shot 2.wav") and labelled from them (`numberedLabel`); bass, melodic loops and one-shots (category `melodic`) are tuned by default. A melodic loop (category `melodicLoop`) is written with one-shot off and loop mode off (`padSettings.ts`, `MELODIC_LOOP_PLAYBACK`, written even with Organize off) and, when its file name states a tempo, with Stretch on by default (the Stretch key on the Tune screen still switches it). Loading a bank again (no question asked) replaces that bank's pads and spares only. A loader with no project open starts a blank one (`blankProject`: one silent pad that loading ignores and the export drops). The project size limit defaults to 512 MB (`packByteBudget`). A dropped folder is a Bank A load. **The first bank load into a new project names it** (`projectNameForFiles` in `samplePack.ts`): "TuneGod - All Kits" for a whole library (the folder's first-level subfolders are named for packs), "TuneGod - {pack folder}" for one pack (they are named for sounds: Kicks, Loops...; a folder with none is a pack too); several folders picked in turn, the first names it. The export file keeps that name as it is (no `_tuned`). Folder inputs live in the menu's parent and must stay mounted outside the menu (closing the menu unmounts them). A kit slot held by a stand-in is no longer replaced separately: Bank A loading replaces the whole kit. **The loaders own placement, labels, colours and tuning defaults**: nothing afterwards moves, relabels or recolours a pad (no Organize sorting, no drum-layout switching, no type-driven moves; only the menu's colour scheme recolours pads, and it does so for every pad at once; correcting a sound's Type keeps the slot in place, moves the corrected sound into hot swap, and fills it with another sound of the intended Type). The only layout is the custom default kit from the product spec (id `horizontal` in `fingerLayouts.ts`: Cymbal, FX, FX, FX / Perc, Perc 2, Perc, FX / Kick 2, Snare 2, Snare 3, Clap / Kick 1, Snare 1, Closed Hat, Open Hat 2; no ghost slots), written by Load Bank A. The empty start screen offers four pixel-icon buttons in a 2 x 2 grid (`dropIcons.ts`: K = Project, open a .koala project; folder under a down arrow = Kit, the kit folder loader; drum = Load Bank A: Drums; K with a person and a note = Chopper) that call the same loaders as the menu (the screen and pads are never resized for them); it has no deck, so its text has the room, and a screen with fewer than 90 text rows (`data-tight`, set by `useOledCell`) drops the words under the icons. A pad that holds a sound shows only its name ("Loop 6"); the slot number shows only on pads with nothing to say.
- **Dragging a pad lays the start screen's four-choice layout over the screen** (`.screen--drag` in `App.tsx`, same markup and classes as the drop zone, icons in `dropIcons.ts`; the hovered choice goes to inverse video, no accent colour): **Hold** (loop the sound until a pad is pressed), **Delete** (a locked pad refuses, with a notice), **Lock** (toggles `Pad.locked`, saved with the pad; says Unlock while the dragged pad is locked; a locked pad shows a padlock in its lower left corner; **a bank load never touches a locked pad**, what the pack brings for its place goes to the hot-swap options, and acapella mode keeps locked pads on bank D) and **Chopper** (asks acapella or chopper mode for that sound: chopper mode takes it as the sample, over 10 s; acapella mode runs `checkStems` on it for its `{label}` / `{label} VOCALS` pair and says what is missing). Holding a pad over a bank key still opens the all-pads view with its Delete and Unused pad targets.
- **Run `npm run build` before every push to main**: Vercel runs it (`tsc -b`, which checks every file with unused-variable errors on), and `npx tsc --noEmit -p .` alone misses most of the app. Five deploys failed (1.0.4 to 1.0.8) because only the latter was run.
- Remote branch deletion returns 403 in the cloud sandbox, so delete merged branches by hand.
- Koala has two EQs: a per-pad EQ in `sampler.json` (`pad.eq`, lo highpass / mid peaking / hi highshelf) and an EQ plugin in `mixer.json`. The measured min and max values in the reference are for the mixer plugin.
- All sound-shaping numbers (loudness trims, per-pad EQ, bus effects, master chain) live in one preset object, `src/audio/mixPresets.ts`. Add a genre by copying it; the guide is `docs/mix-presets.md`. Do not scatter new mix numbers elsewhere.
- **The app runs on a 402 x 874 CSS viewport (an iPhone 16 Pro, installed). Design, build and test for that size only: screenshots, browser tests and layout checks use a 402 x 874 viewport, and no other size or phone is considered.** Layout height is the viewport as reported (`height: 100%`); do not force the screen height on installed iOS apps (it clipped the transport row on iOS 26). Safe areas still come from `env(safe-area-inset-*)` and `useSafeArea.ts`, never from hard-coded numbers. The OLED is a size container: its text is sized in cells and every view must fit its screen at 402 x 874.
- The menu ends with the version line (`package.json` version and the git hash, injected by `vite.config.ts` as `__APP_VERSION__` and `__APP_BUILD__`) and the active mix preset. Bump `version` in `package.json` when something users could notice changes, **then run `python3 scripts/icon/stamp-icons.py`**: it prints the version on the icon's cheek (under the left eye, a plain regular sans (Liberation Sans), black, in the first try's spot, as the user asked) on the saved clean artwork (`scripts/icon/base-dark.png`, `base-light.png`; change the artwork there, never in `public/`) and writes every icon size plus `public/icon-version.txt`, which `iconVersion.test.ts` checks against `package.json`; and check the line when testing a build: the PWA caches the old version until it updates.
- `public/viewport-test/` is a diagnostic page (numbered grid, gradient and a readout of every viewport size) served at `/viewport-test/` on the production domain, which needs no Vercel login, as its own installable web app. The `viewport-test` branch holds the same page alone, but branch previews sit behind Vercel's login. Remove the folder (and the `navigateFallbackDenylist` line in `vite.config.ts`) once the render area is settled.
- Koala mixer behaviour is measured with the projects in `docs/calibration/` (the mix calibration project, `probe-sidechain.koala`, `probe-eq.koala`) and the scripts `analyzeMixRender.py` and `analyzeMixerProbes.py`. Measure with the master chain off first: the master limiter and compressor distort any comparison between renders (round 1's sidechain depth was such an artifact). Velocity is linear (gain = vel / 127).
- New calibration and probe projects put every test in one long pattern (sections back to back, with an empty bar between them), not several patterns, so the user renders one pattern. Write the timeline for that single pattern. All projects in `docs/calibration/` now follow this.
- The menu has two sound-shaping switches (`Switch` in `App.tsx`, the lit key from under the piano). **Organize** is the old Mix and Master chain in one: balance loudness, route to buses, settings by sound type, melodic spread and the master chain (`normalize`, `routeBuses`, `autoPlayback`, `spread` and `masterChain` all read it); **Organize is off by default** (loading a bank never turns it on; `organizeDefaultedOff` in the saved state resets an older saved "on" once). The "Normalize now" preview was removed; the export normalizes. The master style list (Dynamic or Loud, `MasterStyle` in `mixPresets.ts`) sits under it; **Dynamic is the default** (`masterStyleDefaultedDynamic` resets an older saved "loud" once). It never moves, labels or colours a pad. **Sidechain** is its own switch, but the export has no sidechain any more: the switch now turns on the 808 fade-in (below). It needs Organize on and a kick and a bass or 808 on the pads (`sidechainStatus` in `src/audio/sidechain.ts`, worked out from the pads each render, so a hot swap or a new kit locks or unlocks it at once). The export assigns buses from each pad's current type, so routing always follows what is on the pads (tested in `sidechain.test.ts`). The export can no longer write placeholder pads (the writer is gone): every exported pad has a real sample; the on-screen "add FX" and Empty placeholders are never exported. Pads from the loaders are written with the colour and label they show; a sound from an opened project keeps its own.
- `buildTunedKoala` writes into the project's zip (audio, `mixer.json`, `sequence.json`), so `exportProject` in `App.tsx` re-parses `projectFile.current` for every export. Reusing one parsed project for a second export carried the first export's master chain, bus plugins and remapped patterns into it (switching the master style then did nothing and the pattern remap ran twice). Keep that fresh parse.
- A long song can be chopped into section pads (acapella mode) with a pattern each, cut along a grid the user taps out (long-samples prompt, "Chop to patterns for acapella"). The project must hold the song and its Koala stem-split vocal stem (its pad **label** is the song pad's label plus " VOCALS", not the file name; checked by `checkStems` before anything opens): the cuts are found on the song and made on the stem. Section pads are virtual like ghost pads (`Pad.section`, not `isReal`) and are written by `addSongSections` in the export. The cut arithmetic must stay exact to the frame (`planSections` (`tapGrid.ts`), tested), and the editor layout must stay fixed while dragging. Guide: `docs/song-chop.md`.
- The chopped vocal pads are written with stretch on and `stretchLength` = the pattern's bars x the project's beats per bar: Koala counts the stretch length in **beats** (read from `docs/calibration/stretch-5-bars.koala`: 5 bars of 4/4 is 20). That project also records the attack, release and tone knob fields; see "Stretch, attack, release and tone" in `docs/koala-mixer-reference.md`.
- The Tune screen's **pitch slider** is the selected pad's pitch trim (`moveTrim`, `startMatch`, `stopMatch` in `App.tsx`; `PadPanel.tsx`, `PrecisionSlider.tsx`). Grabbing it starts the pad looping at its current tuning with the reference tone on the key; **both play only while it is held** and stop on release, and the pad keeps the pitch it was left at (there is no Correct button and nothing snaps back except a double-tap, which resets the trim to the middle). The slider is `PitchSlider.tsx` and scrubs like every knob and number field (`scrub.ts`: left to right only, slowing smoothly to a tenth of the speed toward the bottom of the screen; waveform and timeline scrubbing is untouched). **Semitone mode** (default): the value lands on whole semitones (detent marks at each of the 25), any cents offset the pad already has is kept. **A tap swaps to cents mode, a double tap resets to the middle** (and leaves the mode as it was): the line bends into a tuner dial with a hand and covers 55 cents either side of the semitone it was on (past that the pitch snaps to the next semitone and the dial centres on it), with ten-cent marks. **Up** (finger above the slider) depends on the sound: a **melodic loop** shows two squares on the screen, Minor at the top left and Major at the top right with the playing chord lit, and the value stays put while the finger is up there; moving the finger onto the other square swaps the reference chord for the relative key's (see below); any other sound has nothing up there. The Tune deck (piano, ALL, TONE) is 12cqw tall, `.deck--tune`; the pad height still reserves `--screen-min` + `--deck-min` (34 + 22).
- **The reference tone has a volume knob and an on/off key.** The pixel knob (`ToneKnob.tsx`, top right of the Tune screen, drag up or down, double tap for the middle; `toneVolume` in `App.tsx`, saved) scales the tone's gain at 0 to 2 times the level matched to the sound (the middle, 0.5, is that level), for the sine and the melodic-loop chord alike (a separate gain after the tone in `startPad`, so it can follow the knob while playing: `setToneVolume`). The **Tone** key (`toneOn`) switches the tone for a tapped pad **and** for the pitch slider (`startMatch`): off, no sine and no chord play and the sound plays alone; the knob dims.
- **Melodic loops are keyed from chroma, not YIN** (`src/audio/pitch/loopKey.ts`, using `chromaOf` and `keyOfChroma` from `song/beats.ts`): the result is the key's relative minor tonic as a whole MIDI note (C major and A minor are one answer), never cents. `shiftFor` moves a loop by whole semitones to the project key (the A4 reference is ignored for loops); anything else it is off by, the user tweaks. The Tune deck's **Minor/Major key** (`keyMajor`, the key beside the piano that used to be All/One; "tune one pad" is gone, a key always retargets every pad) says whether the key picked on the piano is a minor key (default) or a major one (the loop then goes to the relative minor a minor third below). The reference tone for a melodic loop is a soft saw minor or major chord on that key (six detuned saws through a low-pass, `createTone` in `player.ts`); every other sound and the piano keys use a plain sine. The Minor and Major squares (`chord-box` in `PadPanel.tsx`, shown while the finger is above the slider) swap the reference chord for the relative key's (a minor key's relative major, a major key's relative minor), live, until the slider is let go; they never change the project key, and every grab starts on the project key's own chord.
- **Key and tempo from the file name come first** (`src/audio/pitch/nameKey.ts`, tested in `nameKey.test.ts`): a key in a sound's name ("Am", "F#min", "Bb Major", or a bare note beside the word "key") beats every measured key (`analysis.worker.ts`; a loop gets the relative minor, another pitched sound its root, keeping the measured pitch when it already sits on that note). Only capital note letters count, and a bare letter without an accidental, quality or "key" is ignored. A pad whose key came from its name (`Pad.keyFromName`, set by the analysis) is a slightly darker shade of its colour (`darker` in `palettes.ts`, applied in `autoColorOf`): the darkness says the tuning is sure; a key that was only detected leaves the normal shade. Tuning itself ignores the mode: a loop's tonic is stored as its relative minor and `shiftFor` moves it by the shortest distance to the project key's relative minor, which puts any loop in key with any project key. The Tune screen shows the pad's label ("Kick 1", "Melodic Loop 2": `labelOf`) under the key (`NameLine` in `PadPanel.tsx`); a tap swaps it for the file name, which scrolls to and fro when too wide, and it reverts when the Tune screen is left. A number beside "bpm" in the name is the sound's tempo (`Pad.bpm`); it is retained for Koala stretch export (`stretching`, `stretchLength` in beats), configured through Koala Type & pad settings. Tune omits BPM and Stretch controls to leave room for the waveform.
- **The project BPM** (`projectBpm` in `App.tsx`) is edited in the menu's first row (drag sideways: hundredths, 0.02 per pixel; drag up or down: whole numbers, one per 14 pixels, up raises; one axis per press, picked from the first 8 px of movement; `wholePerPx` in `ScrubField.tsx`); opening a project takes its `sequence.json` tempo, a chop takes the song's, and the export writes it back (`writeBpm`). The Tune screen's stretch readout and the SEQ transport BPM both read it. The SEQ Tempo page has no BPM selector (no wheel, no tap): it shows the tempo and holds Quantize, Swing and Humanize, interface only.
- **SEQ (the sequencer)**: a SEQ key beside TUNE, TYPE and SWAP opens `src/components/seq/SeqScreen.tsx` (styles in `seq.css`, sized in `--px`, one 402nd of the phone's width). It is the interface only: nothing on it plays, records or writes a pattern yet, and keys, sliders and switches keep their own state. Pages: Play (the app's own pads for the bank), Velocity, Pattern, Sample edit, Tempo (timing: quantize, swing, humanize), Mixer, Keys (bank D, drawn to the Koala reference's exact geometry) and Sounds (the hot-swap list for the selected pad, shared with the Swap mode through `swapListFor`). The drawings, plan and latency findings are in `docs/seq-designs/` and `docs/seq-sequencer-plan.md`. Back replaces Stop in the transport row.
- **Export rules (they replace any older levelling, tuning or sidechain rules):** (1) **Files are normalized, never turned down for the mix**: every exported file is peak-normalized to `FILE_CEILING_DB` and the mix is each pad's Koala volume knob (`balanceFromStats` in `loudness.ts`; per-type target loudness in `mixPresets.ts` `loudness.targetLufs`, kick on top, hats and cymbals held back; the loaders use the same function). There are no trims, bonuses or crest caps any more. (2) **Every tuning is Koala's pitch knob** (`pad.pitch`, semitones, two decimals: `shiftFor` rounds to 0.01 in `src/audio/shift.ts`, so the preview and the file agree). The only audio that is rendered tuned is **808 and bass**, onto the nearest semitone (`snapSemitones`); the knob carries the rest (`pitchKnobFor`). The analysis reads a bass or 808's pitch from the **second half** of the sound only (`analysis.worker.ts`), where it has settled after its glide. (3) **Per-type pad rules** are in `padSettings.ts` (melodic loops: mute group 4, one-shot on, loop off, modern stretch, bus D; melodic one-shots: no mute group, one-shot off, release max, stretch off; drums: one-shot on, no mute group, loop and stretch off, hats 1, cymbals 2, drum and perc loops 3, bass and 808 5, group 6 reserved for vox loops, chops 7 and up; one-shots never stretch, only loops and chops do, snare tone -0.1; drum and perc loops: stretch in Beats mode; 808 and bass: one-shot on). They are written on every export; only the per-pad EQ is still Organize's. Ordinary loops enable their stretch mode but omit stretchLength (including old guessed lengths), leaving length detection to Koala. Only acapella/synced chop exports write explicit lengths. The stretch mode numbers (`STRETCH_MODE` in `padSettings.ts`: Modern 1, Beats 3...) are read from `docs/calibration/stretch-all-modes.koala`. (4) **No sidechain.** With the Sidechain switch on, every 808 gets a soft raised-cosine fade-in as long as the kicks' main transient (`kickTransient.ts`: the time the peak envelope stays within 6 dB of its peak, median over the kicks, held to 4 to 30 ms, preset `buses.fade808`), rendered into the file and normalized again like the rest. The kick-bus clipper and melodic-bus EQ are written with Organize's bus routing (`busEffects`), not with the sidechain.
- **Colour schemes** (`src/audio/palettes.ts`, `theme.ts`, `SchemeModal.tsx`; the menu's "Colour scheme" row, saved as `paletteId`): about thirty schemes (Organ is the default and Graphite grey). A scheme is ten tone colours (pads and sound types: `colorFor`; chops and chop sections: `chopColor`, the palette's colours in an order that keeps neighbours apart), a lamp colour (`accent`: lit keys and switches, the primary key, knobs, the menu's highlights; `--accent`, `--accent-ink`, `--accent-edge`) and an optional surface hue that faintly tints the chassis, keycaps and menu (`applyScheme` sets the CSS custom properties on the root; no surface hue leaves Graphite grey). Pads, type keys, chops, section pads, the pattern maker and the export's pad colours all read the scheme in use, so changing it recolours everything live (a section pad's colour is its place in the chop, not a stored hex). Thirty-one schemes are taken from palettes picked on coolors.co (`CURATED` in `palettes.ts`: their own colours, the five and six colour ones extended to ten with tints and shades of themselves, assigned to the tones by the arrangement that keeps the rules best and nudged where a palette could not reach them; worked out offline and kept as data; each lamp colour is the palette's first colour (the leftmost on coolors) and the chassis tint takes its hue). The other colourful schemes are generated (`SeedSpec` in `SEEDED`, `buildSeeded`): each has a theme (hue ranges, lightness and chroma ranges) and a seed, and every tone gets its own randomly drawn hue, lightness and chroma, redrawn until the rules hold (every type told apart, snares, cymbals and perc well apart), so no two schemes share a structure; the one-hue schemes (Sepia, Blueprint, Terminal, Amber, Game Boy, Slate, Grayscale) are `PaletteSpec`s in `SPECS`. A new scheme is a `SeedSpec` (change the seed for another draw of the same theme); `palettes.test.ts` holds it to the distinctness rules (snares, cymbals and perc well apart, every type distinct; the one-hue schemes are told apart by lightness like Grayscale).
